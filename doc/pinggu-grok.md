## 1. 总评

**通过，可以冻结为实施基线并启动阶段 A。**

v1.6 的核心问题不是架构差，而是三句话还站在「设计断言」而不是「可失败实验」上：对话记忆论文的分数会被当成文献平台的先验；EDU 六职合一没有退路；产品先建抽取工厂、后验证工作室。v1.9 把这三句都写进了路线图、降级表和质量门。这不是措辞修补，是设计地位变了。

现在真正要盯的，不再是「会不会做成一套知识图谱」，而是 **v1.9 新押上的三笔产品赌注**：

1. **抽取必须用户显式批量发起（D15）**，阅读和问答路径上不按需生成 EDU。这避开了查询偏置和双轨一致性，也把「边读边抽」的工作流缝合推到文档库按钮上。
2. **默认质量门是模型复核，人工不是卡点（D16）**。采用漏斗有了，但复核与生成可能共享同一套参数记忆，阶段 A 若不认真做「同模型 vs 不同模型」对照，会得到虚假安全感。
3. **实体属于平台共享池，项目只有可选关注（D17）**。文档级 EDU 可复用了，身份争论也会变成全工作空间的共享冲突。

这三笔都可以做，而且比 v1.6 的空白更可执行。它们不是否决项，是阶段 A/C 必须单独看见的失败模式。

从 1.6 到 1.9 大约 +774 / −361 行。重心不在加模块，而在把原先「建议以后注意」的评审意见收成决策。按对我 v1.6 评估的响应，分成三类。

这些改动里，最重要的三句是：

1. **「以上是必须被实验验证的产品假设」**（§1.3）。设计文档很少把自身的价值主张降级为假说。
2. **「若人工边界不能稳定复现，粒度规则只能作为提示启发式」**（§7.4）。这等于承认表示过载可能失败，并且预先选择了收缩方向。
3. **L1–L4 写在阶段之前，而不是写在风险附录里。** 失败不会被「已经写了代码」绑架。

### 2.2 故意反向的决策（可以接受，但要按其代价验收）

v1.6 评估建议「按需 EDU 作阶段 B 主路径」。v1.9 明确拒绝：D15、§2.2、§2.3、§14.3，查询时按需抽直到阶段 F，且引入条件很严。

这个反向是对的——如果目标是先有一条干净的主链路。按需会同时引入查询偏置、重复 EDU、升格规则和问答延迟，v1.6 把这些塞进「原文回退」当补丁，实施时一定会先炸。v1.9 改成：

- 解析和 EDU 抽取都是文档库上的显式按钮，互不串联；
- 可以只解析、只读原文；
- 问答遇到无 EDU 的范围，本轮用原文，提示去文档库补抽。

这把「第一次可用」从「等全量 EDU」改成了「原文阅读器 + 可选批量抽取」。产品顺序其实已经纠正，只是纠正方式不是按需，而是 **原文先行、抽取可选、抽取必须确认预算**。

代价见第 5.1 节：阅读中发现一段想分析的文字，必须离开阅读器到文档库重跑范围。这是工作流缝，不是架构错误。

另一处反向：v1.6 评估建议 quote 校验对 OCR 做模糊匹配。v1.9 拒绝自动用相似度放行模型改写（§8.5、§12.6），把解析器文本当作该版本的可引用原文，重 OCR 则出新版本。作为学术工具，这个更严的立场正确。OCR 质量评估被放到阶段 F，也诚实：平台不假装能给扫描件打「保真分数」。产品文案不能写成「忠于原书」，只能写成「忠于该版本解析文本」。

### 2.3 新引入、需要单独盯的决策

D16 模型复核默认采用、D17 平台共享实体池。这两条解决了 v1.6 的运营空洞和作用域分裂，也各自制造了新的失败模式。见第 5.2、5.3 节。

## 3. 仍然成立的结构性优点（不因改版过时）

以下在 v1.9 里仍然是方案的脊梁，不展开成新发现，只确认还在：

- 原文不可变、EDU 可检查、图可重建、引用必须回到固定版本。学术工具的信任链完整。
- 模型不造 ID / 哈希 / 偏移；`contextKey` 只回显；补全三分法；双输入金标准。幻觉高发区被从契约里拿掉。
- 不照搬 EMem-G 的 Argument 节点、默认 PPR、两阶段抽取。论文自己在 LoCoMo 上 EMem ≈ EMem-G（总体 0.780），杠杆在事件式表示不在图传播。v1.9 还把「仅 EDU 文本」写进阶段 A，等于把这条论文结论变成自己的消融，而不是当信仰。
- 九概念 + 取消对象表、延后能力带复活条件，抗腐化结构还在。
- 工程底座：单应用、PostgreSQL、S3 预签名后 HEAD 复核、解析器接口、任务表 + `SKIP LOCKED`、不用 JPA 聚合整表重建。Boot 钉在 4.1.x、Spring AI 钉在 2.0.x，避免口头兼容 4.0 却被 starter 拉到 4.1。

这些足以支撑「可以开工」。下面只讨论 v1.9 之后还值得改、或必须在实验里看见的问题。

## 4. 领域迁移：已经从漏洞变成协议

v1.6 最大的智识风险，是把对话记忆论文读成文献平台的可行性证明。v1.9 处理得干净：

- 源域允许轻度推断、用会话时间戳；目标域禁止外部知识、时间在文本内部——阶段 A 必须用本平台规则，不能把 0.78 当地板或天花板。
- 对照基线改成同文档版本、同权限、同嵌入的原文分块 RAG，并分单篇 / 跨文档 / 千到万级三档（§22.3.1）。
- 经济性按重复查询量算盈亏平衡，而不是只比一次查询的 token。这抓住了 EDU 工厂真正的商业逻辑：一次抽取、多次摊销。摊销不成立就走 L4，不继续扩建。

还需要在实验设计里写死的一句（文档精神已有，避免执行时走样）：**大规模档可以用扩展语料造检索压力，但相关性金标准必须来自真实问题和可核查材料。** §22.3.1 已经写了。阶段 D 退出条件里的「万级文档库」不要理解成「D 必须先有一万份真实研究文档」——那会让问答永远开不了工。应按「已有真实金标准 + 可构造的检索压力」报告，万级是压力上限，不是开门条件。

## 5. v1.9 之后的主要风险

### 5.1 阅读器与抽取按钮不在同一条手上动作里

D15 让主链路变干净，但研究节奏常是：在阅读器里读到「六月四日……诛之」，希望马上看到补全后的 EDU。现在必须记住范围，回到文档库，选版本、选范围、确认预算、等任务。右侧 EDU 栏在抽取完成前是空的，这本身没问题——空状态文案需要说明「去文档库抽取」，并最好能从当前阅读位置带出范围。

这不是要恢复查询时按需生成。那是阶段 F 的事。阶段 B 只需一条产品补丁：**阅读器提供「对当前可见范围 / 当前选区抽取 EDU」的入口，本质仍是创建文档库里的显式批量任务，只是起点在阅读上下文里。** 否则「原文先行」会在真实使用里变成「抽取入口找不到」。

验收：用户不必先理解「文档库按钮」和「阅读工作台」是两个模块，也能对当前屏发起一次带预算确认的抽取。

### 5.2 模型复核可能确认生成模型的同一偏见

D16 的漏斗设计是完整的：确定性校验 → 独立复核（通过 / 疑点，不改写）→ 低风险自动 `Active` → 高影响留在 `Proposed` → 人工可覆盖。复核换提示、不读隐式思维链、阶段 A 比较同模型与不同模型推翻率（§12.2），§24.11 也写了费用翻倍和假阴性。

剩下的硬风险是 **参数知识共振**。生成模型若把「太宗」静默补成李世民，复核模型若读过同一类语料，可能把同一补全判为「上下文充分」。换提示减缓的是格式自我确认，减不了世界知识自我确认。旗舰域偏偏最容易踩这个坑。

阶段 A 必须把「禁止外部知识」样本的复核推翻率单独分桶，不能只报总分。若同模型复核推翻率显著低于跨模型，默认组合就不能是「同一个便宜模型生成再复核」。宁可复核用另一个更强或不同族的模型，也不可用两次同偏差换「已复核」徽章。

「低风险」目前由 §16.8 高影响清单的补集定义，可执行。建议在阶段 A 结束时把自动采用规则写成一张显式表（无外部补全、quote 精确定位、时间解析态 ∈ {已解析, 不适用}、角色在词表内、复核无疑点），避免实施时口头解释。

### 5.3 共享实体池会把身份争论变成全空间冲突

相对 v1.6「项目人物表污染 EDU 文本」，v1.9 的切分明显更好：EDU 文本文档级可复用，链接事后可重跑，关注只是软优先级。冷启动、空关注、集合外实体仍可召回，都写成了质量门。

新问题是历史研究里 **身份本身就是假说**。两个项目可能对「某两个名字是否同一人」持相反立场。共享池 + 合并操作是全工作空间事件（§9.4、§18.4）。宁缺毋错能推迟冲突，一旦有人合并，所有项目的实体页和时间线一起变。

首期单一工作空间可以先接受这个代价，但阶段 C 验收应包含：

- 合并前影响预览必须跨项目（文档已要求预览 EDU 数量，应显示受影响项目）；
- 不提供「项目私有身份视图」时，产品必须让用户理解：关注不是隔离，合并也不是项目内操作；
- 错链的默认动作是拆回未链接或改链接，而不是先合并再指望拆分当日常工具。

不要在 v1 做全球唯一实体库。现在的池是工作空间通讯录，不是 Wikidata。文档删掉了「全球唯一实体库」这项非目标，是因为有了共享池；正文应保持这个谦逊，避免实施时把规范名当成权威传记主键。

### 5.4 阶段 D 的规模门不要卡死问答

千级到万级对照（§22.3.1、§23-D、§24.14）作为**研究问题**是对的：小样本上 EDU 好看、宽范围一问候选爆炸，是这条路线的真实死因。作为**阶段 D 退出的硬门槛**则过重。没有万级真实研究库时，D 应仍能交付有据问答，并提交「当前规模结论 + 压力测试上限」。L4 可以在后续规模实验触发，不必假装第一版问答上线前已经跑完万级。

建议把 D 的退出拆成：D-min（单篇+跨文档问答可用）和 D-scale（规模报告，可与 D 并行或随后）。否则路线图会在「先有数据还是先有产品」上卡住。

### 5.5 写作仍然薄，但不阻塞阶段 A

阶段 E 有备忘、提纲、文章、句级引用、Markdown 导出，仍没有「文章从哪来」：从问答升格、从选中 EDU 拼、还是空白写再挂引用。对研究与写作平台这是产品空洞，但现在主风险在 A–D 的 EDU 假设，E 可以后置。不要在 A 开始前再为写作模型开专题。记下即可。

## 6. 残留的一致性与工程边角

这些不推翻基线，1.9.1 或阶段 B 前顺手清掉。

1. **U4 与角色词表。** §12.4.1 的对象是 `object`（对象），样例 U4 仍写「目标」，§9.2 举例仍有「目标」。应改成对象，或把「目标」收成 `object` 的别名说明。领导者已去掉，这是唯一还挂着的样例漂移。
2. **§10.4 边示例仍只画了 5 种**，正文已说 9 种角色凡链接为实体皆可出边。示例跟上正文，避免实现只建那 5 条。
3. **开放谓词仍列入检索对象（§14.1）。** 宽关系已延后，「谋害 / 暗害 / 加害」会打散谓词过滤。首期应写明：谓词通道只作文档内精确过滤和展示，召回不依赖谓词字符串，主要靠 EDU 向量、原文和角色边。
4. **并发编辑。** 两人改同一 EDU、合并与编辑冲突，仍无乐观锁/版本号。追加式替代（`supersedes`）能兜一部分，实体合并不行。阶段 C 前给 Entity 和 EDU 一个修订号即可。
5. **前端仍是 React + shadcn。** 作为团队栈决策成立；阅读器的长文、简繁、字体、锚点复杂度接近独立产品，估工不要按普通 CRUD 页。不必改选型。
6. **MinerU 本地解析**已有引入条件（§25），敏感材料未进首期交付前可以不实现。一旦有一份不能出网的扫描件进入范围，这会变成阻塞，不是增强项。
7. **工期与人力**仍无量级。作为设计基线可接受；立项时至少标 A 为一人可跑的抽取实验、B 起需要前后端。

quote 精确匹配、OCR 不自评、不按需抽取，这些都是有意识的严，不再当作遗漏。
