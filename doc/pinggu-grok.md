## 1. 总评

**通过。冻结 v1.11，开阶段 A。不要再改 D18/D19。**

v1.11 不是新方案，是一次作用域收束。两件要紧的事：

1. **关掉了 v1.10 评估留下的那条 P1。** `Rejected` 改成文档级质量结论（错误，或对所有使用范围都没有有效信息），并写明不能拿来表示「与当前项目无关」。项目用所选范围、查询和排序管相关性，首期不加项目级隐藏表（§7.7、不变量 8）。这比再加一张排除表更干净。
2. **把 v1.10 的 D19 收回去了。** 实体链接不再按项目保存，改回固定文档版本；引用同一版本的项目复用同一套链接；项目关注实体退出自动链接，只影响人工候选和检索排序（D17/D19、§9.3）。图按文档级 EDU×文档级链接投影，项目只过滤所选版本（D08）。

第二点比第一点大。v1.10 用项目链接解决身份争论，v1.11 把身份争论赶出自动图，赶到研究成果，并给「项目级实体链接覆盖」写了延后条件（§25）。对首期这是对的：EDU、链接、状态、图投影都落在同一粒度——固定文档版本——不再一半文档、一半项目。

代价也明确：同一版本不能在两个项目里维持两套身份图。v1 的安全阀是宁缺毋错（认定不了就未链接）和文档编辑权限（改链影响所有引用该版本的项目）。这套代价可以接受，前提是 **D19 就此冻结**。再翻一次，实施和金标准都会跟着晃。

## 2. 方案现在的粒度（读 v1.11 只需记住这一张表）

| 东西 | 落在哪 | 谁能改 |
|---|---|---|
| 原文、文本单元、EDU 文本、EDU 状态 | 固定文档版本 | 文档编辑权限 |
| 实体链接 | 固定文档版本的 EDU 参数 | 文档编辑权限 |
| 共享 Entity（人/地/组织…） | 工作空间池 | 合并/拆分要平台级实体管理权限 |
| 项目关注实体 | 项目对 Entity 的软标记 | 不改 EDU、不改自动链接 |
| 项目图 | 文档级投影，按所选版本过滤 | 不能覆盖链接 |
| 研究立场、跨文档身份假说 | 研究成果 | 不写回 EDU |

一句话：**文档版本负责「这段话补全后是什么、指谁」；项目负责「用哪些版本、问什么、写成什么」；平台池只做身份索引，不做传记裁定。**

这和 D05（EDU 不是客观事实）、D08（图可重建）、宁缺毋错是同一方向。认定不了的参数保持未链接；需要立场的身份争论先写在成果里，而不是先分裂图。

## 3. 对 D19 收回的判断

v1.10 的项目级链接能让两个项目对同一 EDU 持不同身份结论，图也可以分叉。那是在解决「历史身份即假说」。v1.11 放弃这条，是因为自动图一旦按项目分叉，就会出现：

- 同一文档版本两套链接，复用和评测口径分裂；
- 项目关注实体容易偷偷进入自动链接（v1.10 的排序优先已经踩在这条线上）；
- 修正权限说不清：项目编辑能否改「文档在说谁」。

收回之后，自动链接只看文档内容 + 共享池（§9.3 四步，关注不在里面）。关注只在人工链接界面里提高展示顺序，确认时改的仍是文档级记录，且必须有文档编辑权。质量门 12 专门验「设置关注前后自动链接不变」。这比 v1.10 可复现。

身份争论没有被假装消失，只是换了层：

- 文档上下文不够 → 未链接（检索仍走原文/EDU 文本）；
- 需要跨文档证据或研究立场 → 写进成果；
- 同一版本在多个项目里反复需要不同图结论 → 才引入「项目级实体链接覆盖」（§25）。

**同意这个收法。** 它把 v1.10 多出来的那张 `project_edu_argument_link` 拿掉，领域模型重新变深：同一粒度承担抽取、链接、状态、投影。不要在阶段 A 没跑完之前，因为「两个项目可能吵身份」再把 D19 翻回去。那是已经写好引入条件的延后能力，不是现在的缺口。

## 4. 上一轮 P1 的关闭方式

v1.10 评估的建议是：`Rejected` 只表示错误；项目不想看的 EDU 用项目级隐藏。

v1.11 采纳了前半句，明确拒绝后半句。相关性交给：

- 项目选定的文档版本和章节范围；
- 查询条件与排序；
- 单次检索的实体过滤。

同一章里「与我的问题无关」的 EDU，靠检索排序消化，不为每条 EDU 建项目排除记录。对首期正确：隐藏表几乎一定会和 `Rejected` 再次混用。

界面上还需要一句防呆（阶段 B 实现，不必再改蓝图）：拒绝按钮的说明写成「这条记载是错的或没有信息，会影响所有使用该版本的项目」，不要做成「从我的项目里拿掉」。文档已有语义，缺的是按钮文案。

## 5. 还剩下什么

无 P0，无阻塞阶段 A 的 P1。

### 5.1 【P2】共享文档的编辑权会成为修正瓶颈

EDU 和链接属于文档版本，项目编辑权不能升级为文档修改权（§21.1）。这是对的。共享《旧唐书》某一版时，发现错链的项目成员若没有文档编辑权，只能看、不能改。首期没有「建议改链」流程。

可接受：单一工作空间、文档所有者即编辑者时够用。一旦多项目共用同一版本成为常态，错链会积在只读用户手里。到那时优先做轻量建议/请求，而不是恢复项目级覆盖。阶段 C 验收可加一条：只读项目成员能看到链接、能报告问题，不能静默改文档语义。

### 5.2 【P2】规范名仍可能被读成传记主键

实体页已声明「平台索引，不是权威裁定」，并从项目进入时只展示所选版本的关系（§16.5）。合并仍是全池事件。保持：错链默认改链或退回未链接，合并入口劝退。不必在 v1 做项目私有身份视图。

### 5.3 不要再做的事

- 不要再给 EDU 加项目作用域。
- 不要让关注实体重新进入自动链接。
- 不要为「少跳一次」把阅读器抽回即时生成。空状态带范围回文档库已经够。
- 蓝图不要再为评审意见扩对象。阶段 A 的对照清单（A1/A2）已经写死，去跑。

## 8. 结论

v1.11 把语义记忆的全部可变部分收进固定文档版本：文本、状态、链接、图投影。项目重新变成选择范围和写作的地方，不再是第二套身份账本。这比 v1.10 少一个对象，也少一条裂缝。身份争论被允许存在，但默认存在于成果和未链接值里，而不是存在于两张互相漂移的链接表里。

上一轮要补的那句话已经写上了。再改蓝图，收益会低于把 A1 的金标准标完。

**评估结论：通过。冻结 v1.11，开阶段 A。**

一句话：**粒度已经对齐；用自己的文献去证伪 EDU，别再给项目偷偷开第二套图。**
