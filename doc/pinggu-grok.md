## 2. 方案现在是什么

核心链路没变：

**不可变文档版本 → 文档固有上下文生成的事件式 EDU → 项目内链接到共享实体 → 可重建的项目图 → 原文/EDU/实体混合检索 → 点回固定版本原文。**

相对 v1.9，领域边界更窄、也更干净：

- **D18**：首期没有项目级 EDU。项目问题、笔记、解释只进检索、回答和成果。
- **D19**：人/地/组织的规范对象共享；「这条 EDU 参数是不是这个人」按项目存。同一文档级 EDU 可以在两个项目里链到不同实体或保持未链接。
- **D20**：开放谓词只做展示和用户显式精确过滤，主召回靠原文、EDU 向量、实体和固定角色边。

这三句把 v1.6 里搅在一起的三件事拆开了：文档说了什么、这个项目认为它在说谁、用哪个字符串当检索键。这是对的。图因此变成「文档级 EDU × 当前项目链接」的投影（D08），不再假装存在一份跨项目的事实图。

产品主路径也收束了：解析和 EDU 抽取都是文档库上确认预算后的显式任务；问答无 EDU 时用原文；写作只有「提纲 → 章节材料包（回答 / EDU / 原文）→ 正文」。少做几条平行流程，比再写三个「也可以」有用。

## 4. v1.9 → v1.10：哪些改对了

### 4.1 D19 是对「共享池 vs 身份争论」的正确切分

v1.9 把 Entity 做成工作空间共享池，链接写在文档级参数上。两个项目对「是不是同一人」有分歧时，只能合并或拆共享对象，全空间一起变。

v1.10 改成：共享的是身份索引，争论的是项目链接。`edu_argument` 只保留角色、原文写法、规范值、建议类型；`project_edu_argument_link` 保存项目结论和修订号。项目内改链不影响其他项目；合并/拆分共享 Entity 才是跨项目事件，且要平台级权限、权限安全的影响预览（§9.4、§21.1）。正文写明：这是当前部署的身份索引，不是全球唯一实体库，也不是权威裁定（§9.4、§16.5）。

这比「v1 实体仅项目作用域」更接近真实研究：人可以是同一人，对这条记载的认定可以不同。代价是图查询必须带项目、多一张链接表。这个代价值得，而且和「图是投影」一致。

### 4.2 模型复核从态度变成可执行规则

§12.6 把自动采用写成合取条件，不再靠「低风险」三个字：

- 确定性校验全过；
- 复核通过且无疑点类别；
- 未使用外部知识；
- 摘录字符级精确命中；
- 没有不确定时间继承、类型冲突、角色越界；
- 不替换已被成果引用的 EDU。

自动采用率只作观测，不追高。§16.8 规定通过桶随机抽、疑点桶分层抽，禁止外部知识单独报；不能只用疑点推翻率评价复核。§12.2 把无复核、同模型、跨模型、较小模型都列为消融，无复核不得当正式自动采用路径。

这直接打在 v1.9 评估说的「参数知识共振」上：同模型互相盖章，会在禁止外部知识桶和通过桶漏错率上露出来，而不是被一个漂亮的推翻率盖住。

### 4.3 抽取入口够得到阅读上下文，但没有把按需生成从后门放回来

§16.4：无 EDU 时说明原文仍可检索，链接带上当前版本和范围，**必须回文档库确认范围和预算才建任务**。D15 仍成立。这是正确的产品补丁：缝在导航，不在生命周期。阶段 B 交付清单已包含这项，不要实施时做成纯文案空状态、丢了范围参数。

### 4.4 路线图不再用万级库绑架第一版问答

质量门按阶段挂（§22.6）。D-min 用单篇和跨文档题集交付有据问答；D-scale 才宣称 L1。规模实验还要求：扩展语料可以不全量抽 EDU，但不能把部分覆盖说成全量效果。这避免了两种自欺：小样本宣布胜利，和用稀释覆盖的「万级」宣布胜利。

### 4.5 其余应收尽收的边角

- 样例角色改为 `object`，与词表对齐。
- §10.4 标明边图是非穷举示例。
- EDU / Entity / 链接带修订号，过期写入不能静默覆盖（不变量 14）。
- 定位失败不能 `Active`；降级定位必须显示精度（不变量 15）。
- 多选文档只创建普通独立任务，不造批次对象。
- 阅读器聚合重叠范围为重复候选簇，不自动语义合并。
- 阶段 A 拆 A1/A2：先锁标注说明和计分，再跑对照。
- 阶段 E 指定唯一写作主路径。
- 工期不写进设计基线，另做执行计划（§23 开头）。同意。

## 5. 还剩下的问题

无 P0。下面按会不会在阶段 C 咬人排序。

### 5.1 【P1】EDU 状态是全局的，「拒绝」混了两种意思

D19 让链接按项目保存，但 `Proposed / Active / Rejected / Superseded` 仍在文档级 `edu` 上（§7.7、§18.1）。`Active` 的含义是「可进入默认检索与图投影」。检索范围是项目选中的文档版本，因此：

- 项目 A 把一条共享文档上的 EDU 标为拒绝（错误或「对我无用」），项目 B 默认检索也会失去它；
- 自动采用一旦把 EDU 打成 `Active`，所有引用该版本的项目一起吃进默认池。

「错误」应当全局（文档级 EDU 是错的，就该替代或拒绝）。「无用」常常是项目相关的（这条任职变化与我的问题无关）。现在一个状态词承担两义，和 D19 的方向相反。

阶段 A 只有单工作空间、甚至单项目实验，可以不理。阶段 C 前应写死一条，任选其简：

- **推荐：** `Rejected` 只表示错误或全局无信息量；项目不想看见某条 EDU，用项目级隐藏/排除，不改文档状态。`Active` 仍表示通过质量门、可被各项目检索。
- 或者：采用/拒绝也按项目存——这会再加一张表，和「文档级 EDU 可复用」打架，不建议。

不改的话，共享文档会把修正操作变成跨项目事故，D19 只保护了链接、没保护状态。

### 5.2 【P2】阅读器仍不能在原地确认预算

交接已经够用。若阶段 B 可用性测试显示「跳去文档库」仍丢上下文，再把预算确认做成阅读器上的任务抽屉，底层还是同一类显式任务。现在不要为了少一次跳转恢复即时抽取。

### 5.3 【P2】共享 Entity 的规范名仍可能被读成传记主键

D19 + 界面声明降低了风险，但实体页仍有「规范名称」。合并仍会改写所有项目里指向该对象的链接。权限预览解决的是泄密，不是「我不同意这是同一个人」。只要合并入口够劝退、错链默认改链而非合并，v1 可以接受。不要在阶段 A 为争议身份做项目私有视图。

### 5.4 【P2】写作主路径有了，但材料包与 EDU 状态的互动未写

提纲章节挂上的 EDU 若随后被全局拒绝或替代，§15.5 只说成果标复核。与 5.1 是同一裂缝的成果侧表现。按上面那条状态规则处理即可，不必单开写作对象。

### 5.5 不再当问题的边角

- 前端 React：团队栈，阅读器按长文产品估工。
- 本地 MinerU：§25 有引入条件；不能出网的材料一旦进入交付范围，这项从增强变阻塞。
- 工期数字：已声明不在设计基线里编。
- §10.4 五条边示例：已标非穷举。

## 6. 阶段 A 执行时不要省略的项

这些 v1.10 已经写明。省略任何一项，等于把文档退回断言态。

**A1**

1. 先用试验样本锁定标注说明和计分，再冻结各类型样本量和停止条件；正式对照开始后不得因分数改样本。
2. 中文历史材料为主，现代文档分领域报；双输入；玄武门禁止推断清单。
3. 两名标注者的 EDU 边界 IAA；不够则粒度规则降为启发式。
4. 单一生成模型的抽取、定位、复核基线；禁止外部知识单独分桶。

**A2**

5. 对照：分块 RAG、三元组、仅 EDU 文本、单次结构化、拆分调用。
6. 复核消融：无复核（只测量）、同模型、跨模型、较小模型；看疑点命中率、通过桶漏错率、残余错误率、成本，不看单一推翻率。
7. 最小实体链接：应链 / 应保持未链接 / 别名。
8. 人手 EDU 做一次真实阅读、核对、问答、提纲；结论写成工作面或检索中间层。
9. 每千字成本、盈亏平衡公式和数字。
10. 结束时显式选择 L1 / L2 / L3 / L4。

阶段 B 起才需要前后端。A 不该先建共享实体池和工作台。

## 8. 结论

v1.10 不是新方案，是把 v1.9 已经成立的基线收成可施工契约：链接按项目、采用规则写清、问答与规模验证拆开、阅读器和文档库用手递范围而不是用按需生成偷渡。领域模型因此比 v1.9 更深——更深在 D18/D19 的缝，不在新对象。

剩下那条状态机裂缝，不值得再开一轮蓝图大修。阶段 A 用单项目语料验证 EDU 是否值得成为核心记忆；若值得，阶段 C 把 `Rejected` 收成「文档级错误」，项目不想看的 EDU 用排除而不是全局拒绝。

**评估结论：通过。冻结 v1.10，开阶段 A。**

一句话：**蓝图已经克制且可证伪；去跑自己的语料，并把「错了」和「对我没用」留到做多项目之前拆开。**
