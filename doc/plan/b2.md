# B2：EDU 质量闭环

对照 [dev-landing.md](../../dev-landing.md) §14.3 / §15 / §7.1–7.2 / §9.2 / §12.2–12.3，以及 [blueprint.md](../../blueprint.md) §7.7、§12.3–12.6、§16.4、§16.8、§18.3、§20.2、§20.4、§22.6。[pinggu-grok.md](../../pinggu-grok.md) 只用来定抽取窗口，不另起粒度方案。比较结论见同目录规划讨论，开工以本文为准。

基线：`origin/main`（B1 PR #1–#17 已合入）。#18 纯净阅读顶栏草稿与 B2 无关，不必等待。本文只规划，不改业务代码，不提交 `doc/正史/` 全书。

## 1. 结论

B2 的主修点是组装，不是把 `text_unit` 做大。B0 按段切、B1 写入篇章 `path` 都保留。当前一次抽取只带前一段、没有所属篇章、没有后文；自动采用没有规则版本；阅读器卡片不展示谓词和角色。

做完后应同时成立：

- 一次模型输入含完整 Target、前后邻接、所属篇章；短文档还有题名概览。
- 连续短段按汉字预算合成一次 Target；超长则重叠切开。unit 仍分段存储。
- 低风险 EDU 按版本化规则自动进入 `active`。默认检索只含 `active`。错误输出和候选不进默认检索。
- 编辑者能编辑、拒绝、替代；修订冲突返回 409；人工覆盖模型结论留审计。人工结论在重抽时不被抹掉。
- 阅读器卡片能看见自足表述、状态、谓词和角色。选中后再展开时间、补全和来源精度。

阶段 B 的质量门 2、3、8、9（TXT）在 B2 收口功能与回归；向量、RRF、规范检索文本留给 B3。

仍按落地指南 §15 拆四个功能 PR，另先合一个 CI 修复小 PR（把 `*IT` 绑进 `./mvnw verify`）。不要改成六个工作包，不要清库上线，不要把装填顺序写成概览先行。

## 2. 目标

让批量 EDU 在无人逐条审核时形成可用检索池。用户在阅读器里能看到以后会画到图上的角色。一次抽取不再只有前一段。

退出条件（落地指南 §14.3，不扩写）：

- 满足质量门 2、3、8、9（TXT）。
- 未通过确定性校验的模型输出不进 `edu` 表，只进运行附件。
- `/api/search` 的 EDU 通道只返回 `active`（blueprint §7.7）。`proposed` 只出现在阅读器工作台。
- `rejected` / `superseded` 不出现在默认列表和默认检索。
- 无 EDU 的原文仍能被检索。
- 用户能在卡片上看到角色。
- 抽取输入含所属篇章。

### 4.1 和比较结论第 4 节冲突时的取舍

**多块 Target（`target-1..n`）相对单键 `target`+`spans`：维持当前方案。** 现有提示词和契约示例都是 `key=target`。多块会逼模型自己选键，还容易和「错键到别的块里纠正」绑在一起。`spans` 已经能把摘录映射到窗口里的具体 unit。字符偏移由系统定位写出，不让模型生成 `charStart`/`charEnd`。

**SourceLocator 宽容纠正：维持严格校验。** 模型回显了错误的 `contextKey`，不能因为同窗别处碰巧有这段字，就标成定位成功。那会把邻接摘录当成 Target 主来源。质量门 2 要求采用 EDU 能钉回声明的原文块。

**EDU 列表分页相对「切片阶段不做」：改判，B2 做 `page`/`size`。** 第 4 节把分页和 history 等新资源捆在一起拒绝了。分页本身是落地指南 §7.1 已有的列表约定，不是新资源。窗口化之后按卷抽取，一版可能有大量 EDU；阅读器现在全量拉再在浏览器里按段过滤，会撑不住。阅读器请求必须带 `pathPrefix` 或 `textUnitId`，再分页。不要上游标，不要 history 接口。

**重跑相对 blueprint §20.2：本阶段仍先删后写，但写成已知偏差，并给出方向。** 第 4 节拒绝的是检查点恢复和「不再删可见行」整套任务重写。B2 要做的最小纠正是：显式重抽只删模型来源的 `proposed`/`active`；`rejected`、`superseded` 和 `decision_source=human` 的行保留。不要把「先删后写」说成符合 §20.2。方向是：按处理运行追加候选，用 `supersedes` 连接；完全相同的成功运行可按指纹复用。检查点式租约恢复不在 B2。

## 6. 关键流程

### 6.1 抽取（用户路径不变）

阅读器「前往抽取」仍带当前 `pathPrefix`。文档库勾选全文仍要看段数。不新增 job 类型，不新增篇章资源。

Worker 内顺序：

1. 读该版本全部 `text_unit`（`seq` 升序），按现有规则得到目标下标：单 unit / path 前缀 / 全文；并继续跳过 `StructurePaths.skipEdu`。邻接可以从任务范围外取，但必须在同一结构边界内。skipEdu 节点不能当 Target，也不能当「连续」桥梁。
2. 取结构方案快照：该 `document_version_id` 对应内容提取成功的 `processing_run.parameters`（JSON 即 `StructureProfile`）。找不到且 unit 已有非 `pN` 的 path：按同一完整 path 切窗，运行参数写明 `snapshotMissing`。找不到且 path 为 `pN`：不启用卷/年约束。
3. `planWindows`：在目标下标里按邻居边界切组，再按汉字预算打包，超长重叠切开。
4. 删除范围内**模型来源**的 `proposed`/`active`，再写本 run 的新行。保留 `rejected`、`superseded`，以及 `decision_source=human` 的行（含人工采用后的 `active`）。这是 B2 对现码「范围内全删」的最小纠正，不是 §20.2 的完整语义。
5. 对每个窗口：`assemble` → 模型生成。若一次返回条数超过上限：本窗口结果全部归档到运行附件，一条都不写 `edu` 表，再对半切开（保留 1 个 unit 重叠）重抽。禁止截取前 N 条伪装成功。切开后仍超限则附件+日志，不把超长列表写入权威表。
6. 逐条：定位 → `EduValidator` → 复核（配置开启时）→ `AutoAdoptRules` → 短事务写入。失败输出进 S3 运行附件。同一 job、重叠窗内，规范化后的 `text` + 主来源 `quote` 完全相同则只落一条。
7. `processing_run` 记录上下文策略、自动采用规则版本、窗口数、丢弃数、复核分布。`parameters` 只存窗口 unit 清单、预算参数、prompt 的 sha256 和降级原因，**不存全文 prompt、不存原文块**。

进度：`job.total` = 窗口数，`job.progress` = 已完成窗口。若有窗口归档失败或切开后仍超限，整次 job/run 不得无条件标 `succeeded`。表结构已有 `partial`，B2 至少不要用成功态盖住未完成产出。日志同时打覆盖的 unit 数、token、dropped。

已知偏差（blueprint §20.2）：完整语义是「重跑创建新运行和候选，不覆盖旧结果；指纹相同的成功运行可复用」。B2 不在本阶段做检查点恢复，也不把旧的模型候选全部留着叠加。实现 PR 在 README 写明这条偏差和后续方向（追加候选 + `supersedes`，按指纹复用）。不要用测试把「先删模型可见行」锁成正确的领域规则。

### 6.2 分层上下文

装填顺序固定：完整 Target → 前后邻接 → 篇章 → 短概览。Target 原文不得裁剪。预算不够时从尾部整层丢弃（先丢概览，再丢篇章，再丢较远邻接），不要压缩 Target 给背景让路。Target 过长只允许拆窗口，不允许截断。不要把提示词里的排版顺序（概览写在前面）当成装填顺序。

各层标签与 `contextKey`（稳定，模型只回显）：

| 层 | 标签 | key | purpose | 内容 |
| --- | --- | --- | --- | --- |
| 分析目标 | `[TARGET]` | `target` | `primary-source` | 窗口内连续 unit 正文，用换行拼接。Block 带 `spans`（`textUnitId + start + end`） |
| 前邻 | `[NEIGHBOR]` | `previous-1`（需要时 `previous-2`） | `context-only` | 窗口起点之前、同边界内的 unit。可以在本次 `pathPrefix` 任务范围之外 |
| 后邻 | `[NEIGHBOR]` | `next-1` | `context-only` | 窗口终点之后、同边界内的 unit。同样可出任务范围 |
| 篇章 | `[SECTION]` | `section` | `context-only` | 文档题名 + 当前 path。若窗口首 unit 已有 `ceYear`/`ganzhi`，写成目录附注「（公元 626 年，丙戌）」。这是 B1 已落库的阅读附注，不据此换算 EDU 事件日期 |
| 概览 | `[DOCUMENT_SUMMARY]` | `document-summary` | `context-only` | 文档 `title`、`authors`、`materialType` 拼成一两句。首版不另调模型写摘要 |

主要来源必须落在 `target`。邻接/篇章/概览不能单独证明一条 EDU，也不能单独产出 EDU。提示词 [`edu-generate-v1.st`](../../backend/src/main/resources/prompts/edu-generate-v1.st) 已写过这些层，优先沿用；若增加 `next-1`，只补「key 只能用本次输入已出现的键」。

来源用途：模型输出的 `sources` 项可带 `purpose`：`primary` 或 `context`。缺省时保持现提示词约定，第一条当 primary。允许多条 primary。确定性校验要求：至少一条 primary 的 `contextKey` 是 `target`，且定位不失败。不要让模型输出字符偏移。

邻居边界：

- `noCrossJuan=true`：卷键相同才能作为邻接或打进同一窗口。卷键 = path 中首个匹配 `卷(?:第)?[一二三四五六七八九十百千万零〇0-9]+[上中下]?` 的子串。目录异形的一层 path「卷一 本纪第一 高祖」和目录同形「卷一 五帝本纪第一」都能取到「卷一」。编年「卷第一/周纪一/…」取第一段「卷第一」。path 里没有「卷」时，整条 path 当作卷键，避免跨篇。
- `noCrossNian=true`（编年预置）：年键 = 整条 path（年是叶节点）。不同年不互为邻接，也不打进同一 Target。
- B0 的 `pN`：不启用上述约束。

默认邻接数量：前 1 段、后 1 段。写入配置，不要写进表。现码 `assemble(units, i)` 用的是版本内全部 unit，不是目标下标子集。B2 保持这个语义：邻接可出任务范围，但不能出结构边界。

### 6.3 抽取窗口

窗口是一次 `[TARGET]` 覆盖的连续 unit 下标区间，不是新表，也不是新领域对象。

打包规则：

1. 只在目标下标集合内走。被 `skipEdu` 跳过的 unit 不能进 Target，也不能当「连续」桥梁。
2. 相邻目标若卷键（及年键）不同，必须分窗。
3. 从组首累加 `displayText` 汉字数（按 `codePointCount`，不要用 UTF-16 `length` 当汉字数）。达到上限则结束本窗。
4. 单段已经超过上限：该段单独成窗，仍然不裁剪，不按句切开。
5. 下一窗与上一窗重叠 `overlapUnits` 段（默认 1）。重叠段必须仍在同一边界组内。组内只剩 1 段时不重叠。
6. 短文档（该次任务范围内汉字合计低于上限）：一次窗口吃完，unit 行不变。

起点配置（来自 pinggu-grok，对照后写入 `OntoTraceProperties`，不写进表结构）：

| 参数 | 建议起点 | 配置键 |
| --- | --- | --- |
| Target 汉字上限 | 2000 | `ontotrace.context.target-max-chars` |
| 重叠 unit 数 | 1 | `ontotrace.context.overlap-units` |
| 单次采纳 EDU 上限 | 40 | `ontotrace.context.max-edus-per-call` |
| 前/后邻接段数 | 1 / 1 | `ontotrace.context.prev-neighbors` / `next-neighbors` |

实现 PR-B2-1 必须用下面矩阵跑三份切片，再冻结数字，写入配置和 `evaluation/reports/phase-b2-windows.md`（实现 PR 创建该报告，本规划 PR 不创建）：

- 切片：建成传、太宗本纪摘录、通鉴武德九年。
- `target-max-chars ∈ {800, 1500, 2500}` × `max-edus-per-call ∈ {25, 40}`。
- 观察：建成传能否一次吃完；太宗摘录是否拆成可定位的几窗；通鉴是否按年封顶、年下多段仍是多个 unit；超限是否整窗归档而不是截前 N 条。

### 6.4 自动采用、抽样、队列

规则版本号：`auto-adopt-v1`。写入 `processing_run.auto_adopt_rule_version`。改条件必须升版本，不要改历史含义。

`active` 必须同时满足（blueprint §12.6）：

- 确定性校验通过（现有 `EduValidator`，定位失败已含）。`usedExternalKnowledge` 字段缺失视为校验失败，丢弃，不默认 `false`。
- 复核步骤实际执行，且 `passed=true`、`flags` 为空。抛错、超时、解析失败都不是 passed：该条保持 `proposed`，或整窗按永久错误失败。不得走 B0 那条「复核关闭则只看确定性条件」。
- `usedExternalKnowledge=false`（字段存在且为假）。
- 主要来源 `precision=exact`。块内摘录出现两次不得标 exact。
- 时间不是「只在邻接里出现、Target 里没有 `sourceForm`」的不确定继承。
- 同一 EDU 内相同 `sourceForm` 或相同 `value` 不得给出冲突的 `entityType`。
- 不替代已被研究成果引用的 EDU。阶段 E 之前这条恒为真，不要为它建成果表。

任一条件不满足 → `proposed`。定位失败的条目继续丢弃，不入库。

相对 B0 的行为变化：B0 在 `AI_REVIEW_ENABLED=false` 时，只要无外部知识且定位精确就会 `active`。B2 起这不再算正式自动采用。复核关闭时全部 `proposed`，抽取本身仍可跑。质量门 8 的 live 评测必须 `review-enabled=true`。不改 `application.yml` 的本地默认 `false`。`stub` 网关的复核仍返回通过，便于无密钥走通写库；验收和演示不要用 stub 当质量结论。live 网关的复核请求必须打到配置的 `review-model`，不能和生成共用同一个实际模型调用却在日志里写复核模型名。

抽样不阻塞采用。队列是查询投影，不加审批单：

- 通过桶：生成时被规则写成 `active`，且当时 `review_result=passed`。按 `md5(id || :seed)` 随机抽一小部分。
- 疑点桶：复核**实际执行**且 `review_result=flagged` 或 `review_flags` 非空，按 flag 分组。复核未执行、复核调用失败单独计数，不得并进疑点桶。
- 高影响：`proposed` 或疑点，且命中主体/对象缺失、使用外部知识、不确定时间继承、单条疑为多事件（复核 flag）、定位非 exact。实体链接冲突、纠错建议、成果引用替代放到 C/E，B2 不要做空入口。

人工后来把 `proposed` 改成 `active`、或把 `active` 拒绝掉，**不回溯改生成时的桶**。采用池始终是「生成当时被规则写成 active」的子总体。

阅读器默认列表：`proposed`+`active`，排除 `rejected`/`superseded`。工作台不在点卡片时触发新抽取。这套列表查询与检索查询分开，不要复用 `findVisible` 去喂 `/api/search`。

### 6.5 编辑、拒绝、替代、簇

权限：查看者只读；编辑者/所有者可写。越权 403。查看者拒绝应返回 403，不要改成「从当前项目移除」文案。

- **编辑 `proposed`**：`PATCH /api/edus/{id}`，带 `revision`。同行更新，`revision+1`。冲突 409。不要改成「候选也总是新建 EDU」。编辑同样把 `decision_source` 置 `human`：人工修正过的候选若仍标 `model`，重抽时会被删掉，`before_snapshot` 只留审计不留内容。
- **编辑 `active`**：禁止原地覆盖。走 `POST /api/edus/{id}/replacements`：插入新 EDU（`supersedes_edu_id=旧 id`），旧行 `superseded`。请求必须带旧 `revision`。
- **拒绝**：`POST /api/edus/{id}/reject`，body 含 `revision` 与 `confirmGlobal=true`。未确认则 422，detail 固定为：拒绝表示该 EDU 错误或对所有使用范围均无有效信息，并会影响所有使用该固定文档版本的项目。不得写「从当前项目移除」。
- **人工采用**：`PATCH` 把 `proposed` 改成 `active`。
- 编辑、替代、拒绝、人工采用、覆盖复核结论：都写 `edu_change`，并把该 EDU 的 `decision_source` 置为 `human`。新插入的替代行也是 `human`。
- **确定性去重**：写入前若同版本可见 EDU，或同一 job 重叠窗内，已有完全相同的规范化 `text` + 主来源 `quote`，跳过插入并记日志。近似重复不自动合并。
- **重复候选簇**：同版本、阅读器可见状态、**主来源** `text_unit_id` 有交集，且 `similarity(edu.text)` 过阈值。列表项带 `duplicateIds`。只做成对关系，不要用并查集把 A～B～C 扩成大簇。复用 `V005` 的 `edu_text_trgm_idx`，V009 不要再建同名索引。处置：拒绝候选，或用新的替代旧的。不加簇资源、批次决策、history。「保留两者」只关掉当前 UI 提示，不写库。

显式重抽：见 §6.1 第 4 步与已知偏差。崩溃重试仍然靠「先删模型可见行再写」，避免同一范围双份模型候选。人工行不删。

### 6.6 阅读器

三栏布局不动。右侧从 `ReaderPage.vue` 内联卡片拆出 `EduPanel.vue` / `EduCard.vue`。不要为 B2 建独立的来源面板页。来源精度用文字写在展开区。

卡片默认可见：自足表述、状态、主要谓词、角色（`roleName` 或词表中文名 + `value`）。结构化字段默认折叠；选中后展开时间（`timeValue` / `sourceForm` / 精度）、补全（`value ≠ sourceForm` 时标明）、来源精度（非 exact 必须有文字，不能只靠颜色）。

角色中文名用现有词表：主体、对象、参与者、地点、起点或来源、去向、工具、结果或值、其他。不要为展示加表。

`GET .../edus` 阅读器调用必须带 `pathPrefix` 或 `textUnitId`，并带 `page`、`size`（默认 size=50，按 `created_at, id` 稳定排序）。不要一次拉整版再在浏览器里过滤。

无 EDU 空状态与「前往抽取」保留。点 EDU 仍高亮全部 primary/context 来源 unit。

编辑入口只给编辑者：卡片上「采用 / 拒绝 / 编辑」。查看者看不到写按钮。表单用 VeeValidate + Zod。内容区不要加「EDU 工作台」这类页面标题。

前端继续 `api()` + `types.ts`。不要把 OpenAPI `schema.d.ts` 流水线当作本 PR 前置。

## 10. 建议的实现顺序

先合一个 CI 修复小 PR，再按落地指南 §15 的 B2 四步拆四个功能 PR。每步留下一个会失败的检查。不要把窗口、采用、编辑、卡片一次塞进一个 PR，也不要拆成六包。

### PR-B2-0 CI：把 `*IT` 绑进 verify（先合，非功能包）

`pom.xml` 加 failsafe 插件，让 `./mvnw verify` 执行 `*IT.java`。CI 只跑 `./mvnw -B verify`，而 Surefire 默认不匹配 `*IT.java`，因此 `AuthAccessIT`、`ExtractEduPersistenceIT`、`ExtractEduReviewEnabledIT`、`StructureExtractionIT` 目前在 CI 里都不执行——权限与持久化的集成保护实际缺失。这是现存漏洞，不是 B2 引入的；不先合这一步，PR-B2-1 自己的持久化断言在 CI 里同样不会跑，检查形同虚设。改动只有 pom 与（如需的）测试基类，合入即恢复保护。

### PR-B2-1 组装与窗口

改 `ContextAssembler`、`SourceLocator`、`ExtractEduJobHandler`。配置项先用表中起点数字，矩阵跑完再改冻结值。

必须包含：

- 单键 `target` + `spans`。摘录落在合并 Target 的第二段时 `textUnitId` 为第二段。
- 块内 `quote` 出现两次 → `unit`，禁止第一次 `indexOf` 当 exact。
- 邻接可读任务范围外、同边界内的 unit。
- 缺快照且非 `pN`：按完整 path 切窗，parameters 记降级原因。
- SECTION 附 `ceYear`/`ganzhi` 原文附注，测试断言不把它写进 EDU `timeValue` 的换算逻辑。
- `parameters`：窗口 unit 清单、预算参数、prompt sha256；断言库中没有全文 prompt。
- 同一 job 重叠窗：完全相同 `text`+主来源 `quote` 只落一条。
- 超限：整窗归档、一条不写 `edu`，再对半切开；禁止截前 N 条。
- 三份切片跑 `target-max-chars ∈ {800,1500,2500}` × `max-edus-per-call ∈ {25,40}`，把选定值写进配置和 `evaluation/reports/phase-b2-windows.md`。

检查：`ContextAssemblerTest`——Target 不被裁剪；有 Section；有 `previous-1` 与 `next-1`；连续短段合并；超长重叠切开；`contextKey` 稳定；不跨卷；编年不跨年；`pN` 可合并；有 path 无快照不跨不同 path。`SourceLocator`——第二段命中；重复命中降级。`ExtractEduPersistenceIT`——`contextStrategy` 新值；parameters 能复现窗口而不含原文全文（由 PR-B2-0 保证它在 verify 中执行）。

### PR-B2-2 自动采用、抽样、审计表结构

`AutoAdoptRules`、`review_flags`、`decision_source`、`auto_adopt_rule_version`、`edu_change` 表（本步可先只在抽取路径写规则版本和 `decision_source=model`；人工行在下一步写）。复核关闭不得 `active`。修复 live 复核模型。

必须包含：

- `usedExternalKnowledge == null` 丢弃。
- 复核调用失败 ≠ passed。

## 11. 验收标准

功能：

1. 确认前不写版本、三套结构方案、三栏阅读：B1 回归，B2 不得破坏。
2. 对建成传 / 太宗摘录 / 通鉴切片跑抽取（stub 或 live）：prompt 含 `[SECTION]` 与 path；不再只有 `[NEIGHBOR key=previous-1]`。
3. 编年切片上，邻接与窗口不跨年；纪传切片不跨「卷N」。pathPrefix 任务仍能读到范围外的前后邻接。
4. 复核开启且规则满足时，`active` EDU 的主来源均为 exact，且至少一条 primary 来自 Target（质量门 2）。
5. 丢掉的模型输出不在 `edu` 表；`proposed`/拒绝/替代不在默认检索（质量门 8 的错误出口）。
6. 无 EDU 的段落仍能 `POST /api/search` 命中原文（质量门 3）。
7. 无权用户搜不到该文档原文和 EDU（质量门 9）。B2 写接口同样越权失败。
8. 卡片可见角色；选中后可见时间与精度文字。
9. 编辑 `active` 走替代，不静默覆盖。人工行重抽后仍在。

`EduScoringTest` 口径（只写口径，不写百分比门槛，不算 Wilson 区间）：

- 未判断不算正确。金标准有期望、系统没有判定时，不得记入正确。
- 正式采用池：只统计**生成时**被规则写成 `active` 的子总体。人工后来采用或拒绝，不改这个分母。
- 候选池：生成时 `proposed`。
- 疑点命中率：分母是复核实际执行且 flagged 的样本。复核未执行、复核失败单独计数。
- 通过桶漏错率：分母是采用池。
- 复核后残余错误率：在采用池上统计，不把疑点桶推翻率拿来冒充。
- 禁止推断仍属复核职责，确定性计分不要假装能判动机。

## 12. 风险

| --- | --- |
